A ten-minute path

In order, if you want the argument rather than the archive.

  1. The source hierarchy — 05 · Release-tracking cadence Two facts we'd written down went stale in 48 hours. The retro explains why, and produces a ranking that resolves source conflicts deterministically — a runtime test beats a dev note beats the diff beats memory.
  2. The audit that finds the gaps — 02 · Coverage map Everything the release claims, cross-referenced against what was actually verified, each gap carrying its authoritative source. A gap you've written down is a task; one you haven't is a future correction.
  3. The loop that runs it — 06 · Beta/RC runbook Environments grouped by when they can actually be tested, a four-phase per-drop loop, and a definition of done you can hand to someone else.
  4. The report at the end — 08 · Methods report What all of it produces: a self-contained document a stranger can act on, including the section most reports omit — what I did not cover.

What's deliberately not in here

This package contains public references only. Every external link was verified to resolve for a logged-out visitor, and every referenced tracker ticket was checked against the tracker's own API on July 27, 2026.

One security-classified finding from the 7.1 work was responsibly disclosed through a private channel. It appears here as a bare acknowledgment — no mechanism, location, severity, or reproduction — and the package was grepped to confirm zero traces remain. That scrubbing procedure is itself documented in 10 · Handoff standard, because knowing how to not publish something is part of the job.

Where a method came out of production work, infrastructure specifics — hostnames, connection configuration, stack fingerprints, and other people's names — are omitted. What's left is the transferable part: the method, and why it's shaped the way it is.
